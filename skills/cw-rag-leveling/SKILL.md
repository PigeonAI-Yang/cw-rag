# CW 练级路线排序

用本地 CW 客户端与 CW RAG 快照回答「现在该打什么怪、去哪个地图、哪种武器更快」。这是 [cw-rag](../cw-rag/SKILL.md) 的子 Skill：母 Skill 负责通用静态数据查询，这里专门做练级与武器决策。

## 先决条件

需要一个已构建的 CW RAG 快照（含 `catalog.sqlite`）。复用母 Skill 已知的 `--data-dir`。快照缺失时按母 Skill 的说明处理，**不要在这里重新构建**。

**客户端文件保持只读。** 本 Skill 只读快照与客户端资源文件，不访问网络、不调用模型 API、不自动刷新、不写客户端。

---

## 铁律：不许估算，凡能量取就量取

**这个 Skill 被设计成「先提取再计算」。** 早期的版本在攻击速度上偷了懒——按每个速度级别估一个百分比，结果把 23% 的真实差距估成了 48%，据此得出的「枪比斧慢很多」结论是错的。

因此：

- **攻击间隔**必须用 `cw_attack_speed.py` 从客户端帧延迟算，不许按速度标签猜百分比。
- **单刀伤害**必须由玩家实测填入，客户端里没有伤害公式。
- **减伤规则**是候选值，必须标注来源并允许关闭。

任何一步拿不到数据时，**说清缺什么**，不要用一个看起来合理的数补上。

## 核心工具

### 1. `scripts\cw_calc.py` —— 练级路线排序

路径相对本 Skill 目录解析，不要相对当前工作目录。

```powershell
py -3 "<本Skill目录>\scripts\cw_calc.py" --data-dir "<快照目录>" --level 30 --damage 131
```

| 参数 | 作用 |
| --- | --- |
| `--data-dir` | 必填。快照目录 |
| `--damage` | **必填。游戏内实测的单刀伤害** |
| `--level` | 角色等级，用于推算等级下限 |
| `--level-gap` | 只考虑不低于（等级 − 此值）的怪，默认 15 |
| `--min-level` / `--max-level` | 直接指定怪物等级范围 |
| `--min-nodes` | 单张地图至少要有多少只这种怪，默认 8 |
| `--max-hits` | 最多几刀能杀，默认 3 |
| `--max-seconds` | 最多几秒能杀（需 `--speed-tag`） |
| `--speed-tag` | 武器攻速标签，用于输出「几秒杀一只」与「每秒经验」 |
| `--atk-cap` | 只考虑攻击力不高于此值的怪（更安全） |
| `--max-pdd` | 只考虑物防字段不高于此值的怪（`0` 即只打无减伤的） |
| `--no-defence` | 关闭减伤折算 |
| `--json` | 输出 JSON |

### 2. `scripts\cw_attack_speed.py` —— 真实攻击间隔

把武器的 `attackSpeed` 标签换算成毫秒。已内置从客户端提取的帧延迟表与 60/40 挥砍刺击配比。

```python
from cw_attack_speed import attack_interval_ms, attacks_per_second, family_for_item_id
attack_interval_ms("1432006", 6)   # 枪 Serpent's Tongue，攻速 6
```

### 3. `scripts\read_client_frames.py` —— 从客户端重新提取帧延迟

当客户端更新、或需要复核内置表时运行。**只读客户端**：

```powershell
py -3 "<本Skill目录>\scripts\read_client_frames.py" --client "<客户端 Data 目录>"
```

它打印每个近战动作的逐帧 `delay`，并与 `cw_attack_speed.py` 内置表对比，不一致时报警。

## 排序依据

**主指标：每秒经验 = 每只经验 ÷ 杀一只所需秒数。**

```
实际伤害   = 原始伤害 × 100 ÷ (物防 + 100)      # 见下方「减伤规则」
需要刀数   = ceil(怪物血量 ÷ 实际伤害)
攻击间隔   = cw_attack_speed.attack_interval_ms(武器ID, 攻速标签)
击杀秒数   = 需要刀数 × 攻击间隔 ÷ 1000
每秒经验   = 每只经验 ÷ 击杀秒数
```

「经验/刀」也一并输出，便于与旧结果对照，但**排序以每秒经验为准**——它才是玩家真正的时间成本。

不提供 `--speed-tag` 时退化为按经验/刀排序，并在输出里说明这是退化结果。

## 数据来源与可靠性分级

回答涉及下列任何一项时，都要能说清它属于哪一级。

| 数据 | 来源 | 级别 |
| --- | --- | --- |
| 怪物等级/血量/经验/攻击力/物防 | cw-rag 快照（客户端解析） | 从客户端读出 |
| 挥砍与刺击的帧延迟 | 客户端 `Character_000.wz/00002000.img` | 从客户端读出 |
| 武器倍率（斧 1.92、枪 2.30、长柄 2.70…） | 客户端二进制 `FUN_14025e000` | 从客户端读出（第三方逆向） |
| 每把近战武器 3 挥砍 + 2 刺击 | 客户端 `Character.wz/Weapon` 动作数 | 从客户端读出 |
| 帧延迟的缩放规则 | 社区指南 | **候选** |
| 减伤规则 `× 100 ÷ (物防+100)` | 社区指南 | **候选** |
| 单刀伤害 | 玩家实测 | 实测 |
| 掉落率/服务器倍率/活动加成 | — | **不存在** |

### 攻速数据的可信度

缩放规则是候选值，但**它的两个输入都是从客户端读出的**，且有两个锚点支撑：

1. `attackSpeed` 为 6 时，系数 `(10+6)/16` 恰好等于 1，是恒等变换；而攻速 6 是这个客户端真实存在的标签。
2. 指南给出的算例（长柄攻速 8 → 900 ms）能用内置帧延迟表复现。

实测区间：攻速 4 → 约 720 ms，攻速 8 → 约 900 ms。**两端只差 23%**，不要夸大成「慢一半」。

### 减伤规则

`实际伤害 = 原始伤害 × 100 ÷ (物防 + 100)`。物防 0 时是恒等变换，所以它与所有零物防实测都不矛盾——**但也不构成验证**。

用户想自行验证时，让他打一只**物防 30** 的怪看伤害上限：落在 `原值 × 0.769` 说明反比例成立，落在 `原值 − 30` 说明是减法，不变说明物防无效。

推荐时优先物防 0 的怪（`--max-pdd 0`）；不确定时用 `--no-defence`。

## 必须遵守的判断规则

**1. `--damage` 必填，且必须来自玩家实测。**

客户端没有伤害公式。早期版本试过自动估算，估出 115 而上限实际是 77，**高估 50%**，所以现在没填就直接报错。用户没给时，**请他去游戏里打一下报回数字**，不要替他估。

**2. 报「几刀」时同时报「几秒」。**

只报刀数会误导：攻速不同的武器，同样的刀数花的时间不同。有 `--speed-tag` 时必须给秒数。

**3. 「一两刀砍死」只在低级成立。**

怪物血量增长快于玩家伤害。高级别时说明这一点并改用「每秒经验最高」。这不是装备问题。

**4. 不要为了「更弱」而推荐远低于用户等级的怪。**

低级怪照样给经验，纯按收益排会永远推荐最弱的怪。用 `--level-gap`（默认 15）限制。**客户端没有定义等级差与经验衰减的关系**，所以该参数由用户决定。

**5. 武器建议必须看攻速与盾牌两件事。**

- 攻速用 `cw_attack_speed.py` 算，**不要按标签猜**。
- **双手武器不能同时装盾**。盾牌同等级防御远高于防具，是「不喝药」的核心，所以推荐双手武器时必须说明这个代价。

**6. 未证实的字段不编进公式。**

快照里怪物的魔防、闪避含义未经证实，不要用。`reqJob` 等原始掩码不要翻译成「某职业可穿」。

## 输出要求

先给可执行结论：**打哪只怪、去哪个地图、大概几刀、大概几秒**。再按需给排序表。

保留英文原文怪名与地图名（快照只有英文），中文回答里补中文说明。**不要编造中文译名当成源数据。**

涉及的结论如果依赖候选规则，**一句话说明**（例如「减伤按候选公式折算」），不要展开成长篇免责声明。

## 可视化计算器

`web\cw-calculator.html` 是同逻辑的网页版，依赖同目录的 `mobs.js`、`gear.js`，三者必须放在一起。用 `scripts\export_web_data.py` 生成数据文件。

网页版与命令行口径必须一致：同一套减伤规则、同一套攻速表、都标注实测与候选的区别。
